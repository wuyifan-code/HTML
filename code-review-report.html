十大优先修复项

1

重构 App.tsx 巨型组件

3445 行代码、55+ 个 useState 调用。应拆分为 5-6 个功能 hook 和多个子组件。项目已构建了 useShortcuts、useIframeSelection、usePanelResize 但从未使用。

2

修复 postMessage 安全漏洞

将 "*" targetOrigin 替换为已知的父级 origin。在接收消息时添加 event.origin 校验。涉及 PreviewFrame 桥接脚本和 iframeMessages.ts。

3

CI 流水线添加测试步骤

GitHub Actions 当前只执行 npm install 和 npm run build，未运行任何测试，意味着有问题的代码可直接部署到生产环境。

4

合并 25+ 个样式草稿 useState 为 useReducer

检查器中每次击键都会触发 25+ 个状态比较。改用单个 useReducer 或对象式 useState，可将 25 次渲染降为 1 次。

5

统一 cssEscape 实现

domPath.ts 仅转义双引号（遗漏反斜杠），而 aiStructure.ts 正确转义了两者。这是 CSS 选择器注入防御中的安全隐患。

6

修复 CustomSelect 键盘导航 Bug

activeIndexRef 是 ref（非 state），方向键导航不会触发重渲染，键盘用户看到的高亮永远不会更新。改为 useState 并添加 aria-activedescendant。

7

配置代码检查与格式化工具链

项目未配置 ESLint、Prettier 或 Biome，也没有 pre-commit 钩子。代码风格一致性完全靠人工维护。建议添加 Biome 或 ESLint + Prettier 并接入 CI。

8

拆分 HtmlInputPanel（1069 行）

包含 7 个独立组件，其中 AiTreeControls 约 270 行。应拆分为独立文件，并去重拖放处理函数和弹出层关闭逻辑。

9

AI API 密钥改为后端代理

16 个 AI 提供商的 API 密钥直接从浏览器发送到第三方 API。Gemini 密钥出现在 URL 查询参数中（会被 CDN/代理/浏览器历史记录）。生产环境应通过后端代理。

10

完善无障碍访问

为对话框添加焦点陷阱、prefers-reduced-motion 媒体查询、完整的 ARIA tab 语义、颜色选择器和自定义下拉框的屏幕阅读器支持。

严重问题8 项
▶ 严重 巨型组件：App.tsx 达 3445 行，包含 55+ 个 useState 调用 App.tsx

App 组件承担了 DOM 树管理、AI 提供商集成、导出逻辑（HTML/PDF/PPTX）、快捷键处理、iframe 消息通信、面板缩放、视口管理、检查器草稿状态、剪贴板操作和文件 I/O。严重违反单一职责原则，使代码极难测试、理解和协作。

建议：至少拆分为 5-6 个功能 hook（useAiStructure、useExportPipeline、useInspectorDraft、useViewport、useIframeBridge）和多个子组件（StructurePanel、InspectorPanel、StagePanel、TopBar、StatusBar）。
▶ 严重 25+ 个独立的 useState 用于草稿样式属性 App.tsx:237-263

检查器中每次击键都会触发 25+ 个状态比较。选择元素变化时，同步 effect 调用 25+ 个 setter，每个都可能触发重渲染。这是整个代码库中最严重的性能反模式。

const [draftFontFamily, setDraftFontFamily] = useState(""); const [draftFontSize, setDraftFontSize] = useState(""); const [draftFontWeight, setDraftFontWeight] = useState(""); // ... 还有 22 个完全相同的 useState 调用
建议：替换为单个 useState<InspectorDraft> 对象或 useReducer，将 25 次渲染降为 1 次。
▶ 严重 3 个已提取的 hook 从未被使用（useShortcuts、useIframeSelection、usePanelResize） App.tsx

项目曾进行重构提取了专用 hook，但 App 组件从未使用它们。App.tsx 内联了所有逻辑，存在代码重复、闭包过期风险和脆弱的依赖数组。hook 和内联代码的常量已悄悄分化（如 MIN_SOURCE_WIDTH 在 App.tsx 中是 220，在 usePanelResize.ts 中是 280）。

建议：采用已提取的 hook 并删除内联重复代码。这可以立即减少 App.tsx 约 300 行，并修复多个闭包过期 bug。
▶ 严重 postMessage 使用 "*" 作为 targetOrigin（桥接脚本） PreviewFrame.tsx:697

桥接脚本中所有 window.parent.postMessage(...) 调用都使用 "*" 作为 targetOrigin。虽然桥接令牌提供了应用层认证，但使用 "*" 意味着任何父框架（包括恶意框架）都可以接收元素数据、API 密钥引用和 DOM 结构。

建议：使用 window.location.origin 或已知的父级 origin。同时在接收消息的监听器中添加 event.origin 校验。
▶ 严重 接收 postMessage 时缺少 origin 校验 PreviewFrame.tsx:1621

iframe 的 message 事件监听器仅检查 data.token !== bridgeToken，但从未校验 event.origin。如果桥接令牌泄露（如通过 Referer 头、日志或浏览器扩展），任何来源都可以发送命令操纵 iframe DOM。

建议：在令牌检查的同时添加 origin 校验。记录接受 "null" origin 的威胁模型。
▶ 严重 通过未过滤的颜色值进行 CSS 注入（hover 规则） domPath.ts:270

rule.color 值直接拼接到写入 <style> 元素的 CSS 字符串中。虽然颜色来自编辑器自身的颜色选择器，但如果样式元素被外部修改，正则可能捕获到意外内容。精心构造的颜色值可注入任意 CSS 规则。

`[${HFT_ID_ATTRIBUTE}="${rule.hftId}"]:hover { background-color: ${rule.color}; }`
建议：在拼接前验证颜色值是否匹配严格的 hex/rgb/hsl 格式，或使用 CSS.supports('color', value) 做运行时检查。
▶ 严重 API 密钥暴露在前端代码和网络层 aiStructure.ts:595

全部 16 个 AI 提供商的 API 密钥直接从浏览器发送到第三方 API。Gemini 密钥出现在 URL 查询参数中，会被 CDN、代理、浏览器历史记录和服务器访问日志记录。不存在服务端代理。

建议：生产环境应通过持有 API 密钥的后端代理转发 AI 请求。对于 Gemini，如果 API 支持，应从查询参数认证改为请求头认证。
▶ 严重 CI 流水线未运行任何测试 deploy.yml

GitHub Actions CI 流水线仅执行 npm install 和 npm run build，从未执行 npm test 或 e2e 测试。有问题的代码可以不经任何测试关卡直接部署到 GitHub Pages。

- name: Install dependencies run: npm install --prefer-offline --no-audit --no-fund - name: Build run: npm run build
建议：在构建步骤前添加 npm test，测试失败时终止流水线。

sendMessageToIframeLax 使用 targetOrigin: "*" 发送消息。如果 iframe 已导航到意外的 origin，消息仍会被投递给该外部来源。

▶ 高 未配置 ESLint、Prettier 或任何代码检查工具 package.json

▶ 高 shortcutsWiring.test.ts 使用脆弱的源码正则匹配 shortcutsWiring.test.ts

测试读取原始源文件并使用正则表达式断言代码模式。任何重构（提取函数、重命名变量、重新格式化）都会导致测试失败，即使行为未变。

▶ 高 核心编辑工作流缺少集成测试 src/test/

没有测试覆盖核心编辑流程：加载 HTML、选中元素、编辑文本/样式、验证预览更新。单元测试覆盖了隔离的工具函数，但核心 App 组件及其编辑循环完全未经测试。

▶ 高 巨大的内联 JSX 树无任何 React.memo 边界 App.tsx:1462-2443

整个 UI（顶栏、侧栏、画布、检查器、弹窗、提示）是一棵单体 JSX 树。不存在 React.memo 边界，因此 App 中的每次状态变更都会重渲染整个约 1000 行的 JSX 树。

建议：提取子组件，在 props 稳定的地方使用 React.memo 包裹。
▶ 高 useEffect 依赖数组不完整 App.tsx:459

effect 内部访问了 selected（不仅是 selected?.hftId），但依赖数组仅列出了 selected?.hftId。如果 selection 的引用变了但 hftId 不变，scroll-into-view 不会重新触发。

建议：要么添加完整依赖，要么使用 ref 追踪最新的 selected 状态。
▶ 高 isTrustedMessage 接受 "null" origin messages.ts:147-165

"null" origin 被多种沙箱上下文共享：data URI、file:// 页面、任何来源的沙箱 iframe。桥接令牌检查可缓解此问题，但仅在消息包含令牌字段时生效。

建议：添加注释说明威胁模型。如果桥接令牌始终存在，考虑移除 "null" origin 例外。
