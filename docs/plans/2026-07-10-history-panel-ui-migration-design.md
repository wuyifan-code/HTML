# History Panel UI 迁移设计

## 目标与范围

本次升级以附件 `History Panel.html` 为唯一视觉基线，将右侧历史记录抽屉迁入现有 React 工作台。迁移保留既有 HTML 编辑、选择、撤销、重做和导出流程，不改变 iframe 预览协议，也不扩展到其他面板的整体重做。抽屉采用设计稿中的 340px 右侧浮层、轻量遮罩、56px 时间线条目、当前版本蓝色指示条、变更分类徽标和底部清空入口；窄屏继续使用项目已有的顶部 Sheet 适配。

## 组件与数据流

`App` 负责打开/关闭抽屉、恢复触发按钮焦点并把历史时间线传给 `HistoryPanel`。`useEditorHistory` 继续拥有 `past / present / future`，但每条 `HistoryEntry.summary` 必须描述“如何到达该条目的状态”，而不是挂在前一个状态上。普通提交、文本防抖提交、撤销、重做和版本跳转都共享这一语义，确保用户点击某条“修改文本”记录时实际恢复的是修改后的版本。清空历史仅清除时间线，保留当前文档内容，并把当前状态重新设为唯一基线。

`HistoryPanel` 只负责呈现与操作：行点击触发版本跳转，当前行用 `aria-current="step"` 标识；关闭按钮初始聚焦，`Escape` 关闭；仅在存在两个及以上版本时显示“Clear all history”，避免清空后仍出现无效操作。

## 错误处理与验证

越界版本索引保持无操作，防抖记录在跳转、撤销、重做或清空前先同步落盘。测试覆盖记录摘要归属、跳转后 redo 分支、清空后保留当前内容，以及抽屉的对话框语义与设计类名。交付前运行 Vitest 全量测试、TypeScript/Vite 构建，并在 1440×900 与移动视口下通过真实浏览器检查开关、版本跳转、清空和响应式布局。
